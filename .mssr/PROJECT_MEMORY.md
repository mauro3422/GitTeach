# Project Memory

## Durable decisions

- GitTeach is a standalone evidence-backed developer-profile product; Bridge/MSSR/OmnySys are optional evidence adapters, never runtime requirements.
- Published claims require resolvable provenance. Deterministic Git/repository/GitHub facts do not consume Jev; Jev is only a bounded semantic judge for ambiguity and cannot establish authorship, expertise or seniority.
- Personal attribution remains separate from project truth: preserve `repository-only`, `identity-linked`, `user-confirmed` and `agency-supported`. Git author/coauthor identity alone is only `identity-linked`; observable agency is stronger than self-confirmation.
- AI-assisted/mixed implementation is provenance, not a penalty or guessed percentage. Counts/activity/model confidence are measurements, never expertise or seniority scores.
- Durable architecture is Rust-first/library-first with desktop-first/local-first Tauri 2. Remote repositories use blobless audit identity plus transient selected hydration; clone-once workspaces remain reference/fallback. The pre-rebuild Electron product is archived only for recovery at `archive/legacy-electron-v2.89` / `legacy-electron-v2.89-final`, not kept as an active runtime. The verified F9 webview remains vanilla until a presentation-only Svelte 5 + Vite migration preserves the same Rust/Tauri contracts.
- F9 product persistence is app-local SQLite. Repository/audit identity, bounded repository/personal derived views and exact-profile direct private interview answers may survive restart; raw source/excerpts/cache internals do not. F9.3a private answers reload only under the exact actor + repository-set profile and never imply consent. Publication/approval stays hard-disabled until an explicit later decision after extended testing. Restored state is continuity data, never freshness proof.

## Working style

- Prefer deterministic extraction before semantic calls.
- Cache semantic work per candidate from exact evidence/question/context/provider-policy identity; preserve historical ambiguity/contradictions, never persist raw excerpts, and bound reuse age for floating provider aliases.
- Prefer observable action verbs over generic `knows X` language.
- Personal surfaces may show connected-project statistics/tendencies with provenance; personal action claims still require actor/self-report evidence.
- Local Git tags and GitHub Releases are different facts; never infer one from the other.
- Authenticated GitHub HTTP cache must be partitioned by a stable non-secret connection identity; if no partition is available, authenticated caching stays disabled.
- GitHub collaboration stays descriptive: observed counts remain separate from repository support/coverage and never become quality/seniority; `PENDING` reviews are facts, not submitted review activity.
- Profile declarations remain private upstream by default; publication requires explicit `approved` consent and passes through a bounded context that strips authorization/internal-source metadata.
- Historical technology evolution uses real bounded Git commit-tree snapshots only; it never checks out history, interpolates missing commits or turns language/file evolution into a developer-skill score.
